DFU stopped: what to do next

  1. Keep power and USB connected. The update may be incomplete; neither the old nor the new firmware is confirmed to start. The flasher sent no further reset or flash after the error; the radio may restart on its own.
  2. Close other serial terminals and apps using the radio.
  3. After the transfer has stopped, check the USB connection. If needed, try a known data cable connected directly to the computer.
  4. If this is a standard RAK4631 with the Adafruit-compatible bootloader, double-press its RESET button to enter bootloader mode. A RAK4631-R or a different installed bootloader may need different steps.
  5. Choose the same physical radio's DFU USB port. Keep or reselect the exact validated ZIP for the interrupted operation and your board, inspect it again, and review the operation before choosing to retry. This error alone does not call for an erase or bootloader replacement.

Identify the exact interrupted operation and check the radio's state before choosing any reset or retry. For a bootloader or SoftDevice change, do not reset or retry until its state has been assessed; ask for help if unsure.

If an erase or recovery step was already pending, follow the retained recovery instructions for that step. An acknowledged packet does not verify the flash or prove startup.

USB reconnect trouble · virtual machines & older firmware

If the bootloader port disappears, pause VMs configured for USB auto-capture, or disable that radio's automatic VM passthrough before retrying. A VM may claim the newly enumerated ROM/DFU device; do not assume it will be returned after 30 seconds. The page cannot reclaim USB from a VM or restart a Windows driver. Re-select the same radio after the host regains it.

Some older ESP32 TinyUSB firmware stalls during bootloader entry on a direct Windows root USB port. A USB hub or another port routed through an internal hub can help. No administrator CLI command is part of the browser workflow. Never interrupt an active partition-migration bridge merely because it temporarily disappears.

Full Companion text mode

Use only for a running Full Companion in text mode. Binary handoff may turn USB logging off. nRF52 flashing uses its serial DFU port, not a mounted drive.

nRF52 erase & DFU options

The final image is validated before erase. Wipe requires its own acknowledgement, separate from a board override. After erase, select the same physical radio’s DFU serial interface; no mounted drive is used.

Backup & startup preferences
Backup & restore

Export settings without flashing, or restore to the same board or deliberately move to another.

Backup interface override - normally automatic

Save and verify node settings, then use Import JSON to restore them. Each backup lists any values not captured. Firmware/bootloader images, stored messages and runtime logs are not included. Keep the JSON private; backup requires the application port, not ROM/DFU.

Ripple standalone backup

Keep Ripple running normally. Back up Ripple reads and verifies its private identity over built-in ESP32-S3 USB, then restarts the device normally. Use desktop Chrome or Edge. If direct USB is unavailable, select the Ripple folder from its SD card.

USB captures the verified key and firmware information. Adding SD files also preserves original contacts, channels and preferences as files. Maps and recorded tracks are excluded. Files stay on your computer. Restore the identity over USB to a MeshCore companion or Wadamesh, or download a Wadamesh identity file for its on-device Import settings.

Wadamesh settings backup

Select the running device's application USB port, then back up its identity, channels, contacts, radio, position, BLE PIN and other supported mesh settings. Import this JSON to restore over USB with readback checks.

For display, keyboard, Wi-Fi and other preferences unavailable over USB, add the original meshcomod folder from SD, or an exported prefs folder from internal storage. Download saved files and copy them back while the device is off, using the same device and storage layout. Maps, message history, tracks, logs and oversized files are excluded. Backups stay on your computer and contain secrets.

The Wadamesh settings download works with its on-device Import settings: identity, name, radio, position, channels and contacts. Keep the browser backup for USB restore of contact routes, repeat, path hash, BLE PIN, telemetry and other captured settings.

May contain private identity and channel secrets. This copy stays in page memory only; it is not uploaded or saved in browser storage. Copy it only to a trusted private location.

Restore preview

Repeater settings use the serial console and are checked after writing. Complete public region snapshots include hierarchy, flood permissions, home and default scope; they merge without deleting unrelated target regions. Unsupported or uncaptured settings are skipped with reasons. No firmware, partition layout, messages or logs are restored. A restore is not atomic; keep power connected.

Direct on this page

Requires your permission
Use desktop Chrome or Edge with Web Serial. Port selection, reconnects and downloads remain explicit. CH340 and other UART bridges use the OS serial driver; the page cannot install it or change Raspberry Pi USB speed. Firmware hosts may require Download → local file because of CORS.
Explicit limitations
No unreviewed partition migrations or arbitrary commands from imported JSON. Unparseable and unavailable settings are reported, not replayed. Settings backups exclude firmware/bootloader images, stored messages and runtime logs; other uncaptured values are listed for each backup. A completed transfer is not proof of application startup.
